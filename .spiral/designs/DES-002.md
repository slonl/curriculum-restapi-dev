# Design: Semantic Continuity Probe Shape

## Role

Defines the smallest useful experiment shape for Cycle 2 before any AI-assisted
mapping work is attempted.

## Why This Exists

Cycle 2 needs decision-quality evidence about semantic-continuity feasibility,
not a production integration. The maintainer identified FO
(`slonl/curriculum-fo`) as the latest dataset and leerdoelenkaarten
(`slonl/curriculum-leerdoelenkaarten`) as an earlier different version, with
possible shared references to `curriculum-examenprogramma`, `curriculum-basis`,
and `curriculum-kerndoelen`.

The experiment therefore needs a bounded comparison sample that can expose
renames, moved concepts, changed modelling, splits, merges, broadened/narrowed
scope, and likely non-links without pretending to solve the complete migration.

## Cultural Influence / Constraints

The cycle is deliberately neutral about whether AI is appropriate. Because
durable third-party references are a trust boundary, plausible AI output is not
enough: every proposed continuity relation must be auditable from source data
and clear rationale.

## Behavior / Responsibilities

The probe should:

- use local dataset checkouts as read-only experiment input;
- compare a small semantic slice from FO against the relevant older
  leerdoelenkaarten material;
- include nearby graph context rather than isolated labels;
- record candidate continuity links, non-links, split/merge hypotheses, and
  uncertainty;
- separate AI-generated suggestions from human/audit conclusions;
- produce a recommendation that can be positive, negative, or conditional.

## Boundaries

What belongs here:

- sample selection;
- mapping rubric;
- evidence extraction for the sample;
- AI-assisted mapping experiment;
- audit notes and feasibility recommendation.

What must remain outside:

- production `replacedBy` data mutation;
- whole-dataset migration;
- Open Data maintenance architecture changes;
- maintainer-workspace feature implementation.

What change should this boundary protect us from:

- accidentally turning a feasibility probe into a data migration or product
  design commitment.

## Supporting / Intrinsic Work

| Support | Why necessary |
|---|---|
| Record exact local checkout commits before mapping | Keeps experiment evidence reproducible enough to audit |
| Extract compact graph context around sampled entities | Semantic continuity depends on hierarchy and neighboring concepts, not only names |
| Define confidence/rationale fields before using AI | Makes output reviewable and reduces false certainty |

## Alternatives Considered

| Alternative | Why Not Now | Evidence / Trade-Off |
|---|---|---|
| Compare whole FO and leerdoelenkaarten datasets | Too large for a first feasibility cycle and would obscure audit cost | Cycle 2 is a research probe, not a migration |
| Use only entity titles for matching | Too likely to miss moved/split/merged concepts or overfit names | The source concern explicitly includes renamed and redistributed concepts |
| Require historical ground truth first | No known successful historical split/merge migration exists | The cycle must still produce useful conditional evidence |

## Complexity / Maintainability Check

- Concepts introduced: semantic slice, candidate continuity link, audit
  rationale, uncertainty class.
- Dependencies introduced: none in production code; read-only use of local data
  repositories.
- Expected change radius: `.spiral` evidence plus temporary/local experiment
  scripts or notes if needed.
- Replaceability considerations: the probe should be discardable if AI proves
  unhelpful.
- What would make this harder for a future agent/human to change: undocumented
  sample choice, unrecorded repository revisions, or AI output without evidence.

## Verification Plan

The design is realized when the cycle records:

- exact dataset input revisions;
- chosen comparison sample and why it was chosen;
- mapping rubric/output schema;
- AI-assisted mapping output for the sample;
- audit findings that distinguish useful, wrong, uncertain, and unauditable
  suggestions;
- a recommendation about roadmap relevance and conditions.

## Deferred Decisions

- Whether semantic-continuity assistance belongs in the maintainer-workspace
  roadmap.
- How a production workflow would store, review, and commit `replacedBy`
  changes.
- Whether any specialized retrieval, embedding, or graph tooling is warranted
  beyond this probe.
