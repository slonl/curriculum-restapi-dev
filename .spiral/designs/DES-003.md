# Design: Semantic Continuity Mapping Rubric

## Role

Defines how Cycle 2 should classify AI-assisted continuity suggestions for the
Nederlands havo sample.

## Why This Exists

The research question is not whether AI can produce plausible semantic matches,
but whether it can make trustworthy continuity maintenance cheap enough to be
practical. The sample therefore needs an explicit review rubric before mapping
suggestions are generated.

## Cultural Influence / Constraints

Durable third-party references are a trust boundary. A suggested relation must
not be treated as safe merely because it sounds reasonable. The rubric favors
auditable uncertainty over confident but ungrounded links.

## Behavior / Responsibilities

Every candidate relation must record:

- source entity and target entity IDs;
- source and target labels/descriptions;
- graph context used;
- proposed relation class;
- evidence summary;
- counter-evidence or uncertainty;
- confidence;
- reviewer action.

Relation classes:

- `exact-or-near-continuity`: same educational concept, wording/model changed
  only modestly.
- `narrower-than-source`: target represents part of the source concept.
- `broader-than-source`: target covers the source plus additional scope.
- `split`: one source plausibly continued by multiple targets.
- `merge`: multiple sources plausibly continued by one target.
- `related-not-continuity`: semantically related but not a durable-reference
  continuation.
- `no-link`: evidence argues against a continuity relation.
- `insufficient-evidence`: plausible but not enough context to judge.

Confidence levels:

- `high`: enough textual and graph evidence for a domain expert to review
  quickly; still not auto-commit.
- `medium`: useful shortlist item, but needs human/domain review.
- `low`: useful mainly as an explored alternative or negative example.
- `reject`: should not be proposed as continuity.

Reviewer actions:

- `accept-for-human-review`
- `needs-more-context`
- `reject`
- `defer`

## Boundaries

What belongs here:

- classification language for the experiment;
- minimum evidence expected in AI suggestions;
- safety expectations for interpreting output.

What must remain outside:

- production `replaces` / `replacedBy` mutation;
- a permanent data model for maintainer-workspace review;
- automation thresholds for unattended migration.

What change should this boundary protect us from:

- turning a research probe into an implicit promise that AI can directly edit
  continuity links.

## Supporting / Intrinsic Work

| Support | Why necessary |
|---|---|
| Keep relation class separate from confidence | A split can be well evidenced or speculative |
| Include counter-evidence | Prevents plausible one-sided explanations from looking stronger than they are |
| Require reviewer action | Keeps the output maintainer-oriented instead of model-oriented |

## Alternatives Considered

| Alternative | Why Not Now | Evidence / Trade-Off |
|---|---|---|
| Binary match/no-match | Too crude for split, merge, broadened, narrowed, and related-but-not-continuity cases | The cycle source explicitly names these changes |
| Numeric similarity score only | Hard to audit and easy to over-trust | The cycle asks for trustworthiness, not only retrieval |
| Auto-commit threshold | Out of scope and unsafe for a feasibility probe | No production mutation in Cycle 2 |

## Complexity / Maintainability Check

- Concepts introduced: relation class, confidence, reviewer action.
- Dependencies introduced: none.
- Expected change radius: Cycle 2 evidence only.
- Replaceability considerations: this rubric is disposable if the experiment
  shows a different review vocabulary is needed.
- What would make this harder for a future agent/human to change: mixing AI
  confidence with accepted domain truth.

## Verification Plan

The rubric is useful if mapping evidence can use it to distinguish strong
continuity candidates, partial/split/merge cases, and rejected plausible-looking
matches without mutating production data.

## Deferred Decisions

- Whether these relation classes should become maintainer-workspace UI states.
- Whether confidence should later be calibrated against human-labeled examples.
