# Design: one-object audit trail vertical slice

## Boundary

One coordinated cycle spans the embedded `curriculum-store`, embedded
`curriculum-rest-api`, and their `curriculum-restapi-dev` gitlinks. The store
adopts the released history implementation; the REST API translates one current
UUID into its object history; the browser adds one read-only route. The parent
contains intent/evidence and pins the evaluated child commits.

## Store adoption

Update `@muze-nl/simplystore` and its lockfile from `^0.11.2` to `^0.12.0`.
Extend the existing real-runtime fixture so curriculum-shaped records are
changed by successful commands carrying author and message. Assert that
`meta.history.get(currentObject)` returns the base and changed versions in order
with the expected immutable contents and compact command metadata both live and
after reopening.

No curriculum command, schema, data or persistent format changes are needed.

## Store query contract

Add a small dedicated query module in `curriculum-rest-api`. It:

1. finds the current record with
   `meta.index.id.get('/uuid/' + request.query.id)`;
2. returns `null` when no current record exists;
3. calls `meta.history.get(record)` rather than string lookup so the record's
   ownership history survives intermediate ID removal/restoration; and
4. projects only version, timestamp, compact command metadata and historical
   object.

Use the normal `/query/` endpoint. This is a bounded lookup for one object, not
the dataset-wide `/slowquery/` use case. Existing configured query limits remain
the capacity and failure boundary.

## REST contract

Add `opendata.api.History` and `GET /uuid/:id/history` after the existing Basic
authentication middleware. It returns 404 for a `null` query result, otherwise
sets `Cache-Control: no-store` and responds as `application/jsontag`. JSONTag
preserves historical object attributes, links and identity without inventing a
lossy generic JSON-LD transformation. Existing store failures become the
current bounded 500 JSON error response.

The response is an oldest-first array. Each item is:

```text
{
  version,
  timestamp,
  command: null | { id, name, author, message, version, timestamp },
  object
}
```

## Browser view

Add a `Geschiedenis` link to the ordinary item template. The link targets
`/uuid/:id/history/`. A separate route and action fetch through a
`localAPI.history(id)` adapter using JSONTag response parsing.

The audit template shows:

- a back link to the current object and its current title;
- visible loading, empty and failure states;
- one chronological entry per stored version;
- base-version labeling, timestamp, author, message, command name and version;
- an expandable preformatted JSONTag snapshot.

The action uses a request token so a late response cannot overwrite a later
navigation, following the established orphan-view pattern. `clearView` cancels
ownership of the request. The view is read-only and does not participate in the
editor's local pending-change model.

## Verification

- Curriculum-store real-runtime coverage before and after restart.
- REST query projection, authentication inheritance, 200/404/500 behavior,
  no-cache header and JSONTag preservation.
- Browser route, object-view link, loading/failure/stale-response behavior and
  rendered base/command entries with snapshots.
- Existing store and REST API suites and lint.
- Parent exact gitlink diff and `docker compose config --quiet`; start a
  disposable Compose path if practical without touching maintainer data.
- Spiral staged, range, snapshot and prospective-integration validation.

## Alternatives rejected for this cycle

| Alternative | Reason |
|---|---|
| Metadata-only JSON response | Loses JSONTag object attributes/links or requires a new generic JSON-LD mapper |
| Property-level diff | Adds schema and array/link semantics beyond a simple audit trail |
| Reuse the full item renderer | Couples historical immutable objects to editing/local-change behavior |
| Global command browser | Reverses the confirmed object-first scope |
| Pagination now | The maintainer selected the complete history; existing result limits provide an explicit bound |

## Deferred work

Frontend modernization may later replace the small template without changing
the REST contract. Diffs, restore, same-version peers, command-wide audit,
original inputs and whole-dataset time travel remain separate decisions.
