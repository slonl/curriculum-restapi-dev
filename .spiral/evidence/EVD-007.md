# Verification Evidence: Semantic Continuity Feasibility Report

## Claim Being Verified

Cycle 2 produced enough first-pass evidence to decide whether semantic-continuity
assistance deserves consideration as a maintainer-workspace roadmap capability.

## Why This Evidence Exists

The cycle goal was not to implement production continuity mapping, but to decide
whether AI-assisted semantic continuity mapping is promising, unsafe, or
conditional enough to guide future roadmap work.

## Result

Recommendation: **conditional positive for roadmap exploration as review
assistance; negative for unattended continuity-link creation.**

What the cycle learned:

- The initial Aardrijkskunde plan was wrong for FO-vs-LDK because FO has no
  Aardrijkskunde yet. The process caught and preserved that correction.
- Nederlands havo is a better first sample because both FO and LDK contain
  relevant data, existing continuity anchors, and unlinked candidates.
- A very small literature slice was enough to expose real modelling drift:
  FO models literature as "Literatuur als systeem" and "Literatuur in
  beweging"; LDK models fiction reading as reading object and task quality.
- AI could produce a useful shortlist and, importantly, could identify
  plausible-looking non-links.
- The strongest suggestions were still only medium-confidence review items, not
  trustworthy automatic links.

Practical implication:

AI assistance looks potentially useful if presented as a maintainer review
queue with evidence, counter-evidence, relation class, and uncertainty. It does
not yet look suitable for automatic `replaces` / `replacedBy` mutation.

Conditions for future roadmap work:

- Use AI to propose candidates, not to commit links.
- Include graph context, predecessor entities, and level/subject resolution in
  the prompt or retrieval context.
- Require explicit `related-not-continuity`, `no-link`, and
  `insufficient-evidence` outputs.
- Have a domain expert validate multiple samples before treating this as a
  first-class maintainer-workspace capability.
- Measure reviewer effort: the value depends on whether the shortlist is faster
  than manual search.

Recommended next evidence if this direction continues:

- Run the same rubric on one more Nederlands havo slice, probably
  `Domein A Communicatie`, because it should test split/merge behavior across
  speaking, writing, reading, and interaction.
- Include predecessor/deprecated entities and `doelniveau` text in the
  extraction, because sparse LDK active labels limited confidence.
- Ask a human/domain reviewer to mark the current literature suggestions as
  accepted, rejected, or missing important candidates.

## Failure Cases / Limits

This cycle used one small sample and one AI-assisted pass by Codex. It does not
establish model reliability, recall, precision, or total migration cost.

The current evidence is enough to justify continued roadmap exploration, but
not enough to commit product architecture or production data changes.

## Evidence Quality

The evidence is decision-quality for a first feasibility gate because it
includes a failed sample choice, a corrected sample, an explicit rubric, a
bounded extraction, candidate mappings, non-links, and limitations. It is not
acceptance evidence for a production feature.
