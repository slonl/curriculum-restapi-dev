# Self-healing Compose restart evidence

Observed on 2026-10-14 for the curriculum-store pin at 76e21b1, which points
to curriculum-store b3d6faa and SimplyStore 0.11.2.

## Setup

The committed `docker-compose.yml` was run with a temporary override under the
separate project name `curriculum-recovery-test`. The override changed only the
curriculum-store container name and host port and mounted a disposable data
directory over `/home/node/app/data`. Only curriculum-store was started, with
`--no-deps`; the existing development containers and dataset were not used.

The disposable store contained one `RootType` entity whose title was
`recovery-fixture`, plus the generated integrity manifest and indexes. Startup
ran the Compose service's normal `npm install` followed by `exec npm start`.

## Result

1. The initial `docker compose up -d --no-deps curriculum-store` started the
   service, and an HTTP query to `/query/` returned status 200 and
   `[{"title":"recovery-fixture"}]`.
2. The live lock identified token
   `08a03257-35fa-4fb6-82e2-4ca358a47584`, PID 29, and container host
   `0bbe0acdab20`.
3. `docker kill --signal KILL curriculum-store-recovery-test` stopped the
   container with exit 137 (`OOMKilled=false`). The lock and its original owner
   metadata remained; nothing removed or edited it.
4. The same Compose `up` command restarted the existing container without
   administrator intervention. SimplyStore logged:

   ```text
   Store ownership took over /home/node/app/data/.simplystore-lock from stopped owner 29@0bbe0acdab20 (started 2026-10-14T08:45:50.980Z); the owner's socket refused connections
   ```

5. The takeover audit recorded proof `ECONNREFUSED`, the complete previous
   owner record, and new token `42f60a3d-fc0c-40b6-88bc-4ad9c1cdd1a1`.
6. After takeover, the same HTTP query again returned status 200 and the same
   fixture value.
7. A final normal `docker compose stop curriculum-store` exited 0 and removed
   the lock directory. The disposable container and network were then removed.

This demonstrates the extended request's required path: a SIGKILL prevents
normal lock cleanup, and the next Compose startup recovers without manual lock
removal only after SimplyStore obtains liveness proof that the previous owner
is gone.

## Supporting checks

At b3d6faa, the curriculum-store suite produced 44 passing assertions with
Tap coverage enforcement disabled. This included conversion and integrity,
queries, commands, persisted indexes, and readback after restart.

The default `npm test` command still exits nonzero because Tap enforces complete
coverage while reported statement coverage is 84.78%. `npm run lint` also exits
nonzero because the project uses ESLint 9 without an `eslint.config.*` file.
These are upstream project-tooling defects, not failures of the observed
runtime behavior.

## Limits

The test used a minimal valid disposable dataset and started only the store
service. It does not exercise takeover from a live or ambiguous owner, an
unfinished command, legacy ownership metadata, or multi-host storage; those
cases remain protected or require administrative recovery. No automatic
restart policy was tested or added.
