# Active command polling compatibility verification

Observed on 2026-10-14 for parent correction commit `d76acbd`, which pins
curriculum-rest-api `a783d42` on
`spiral/CYC-20261014-1ZG1H-22-object-audit-trail`.

## Evaluation finding and cause

The maintainer's real editor workflow accepted a command and then displayed
`Invalid command: active: undefined`. SimplyStore 0.12.0 defines `accepted` and
`active` as nonterminal command states, followed by `done`, `failed` or
`unsafe`. The REST API correctly forwarded the store status. The browser's
`pollCommand` implementation, however, continued only for `accepted` and
returned every other state to the caller. The caller consequently rejected
the valid `active` transition because it expected `done`.

This is a compatibility regression exposed by the cycle's SimplyStore upgrade,
so it is corrected inside the current cycle rather than deferred.

## Correction

REST child commit `a783d42f323efb69f9091c470b67d19216c9f86a` makes the browser poller:

- continue through both `accepted` and `active`;
- return terminal and unrecognized statuses to the existing caller;
- prevent overlapping status requests;
- enforce an independent 30-second deadline rather than comparing a poll count
  with a millisecond value; and
- clear the interval and deadline after success, timeout or request failure.
