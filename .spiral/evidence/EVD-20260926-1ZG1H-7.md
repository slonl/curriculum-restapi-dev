# Clean Docker shutdown evidence

Observed on 2026-09-26 for the change at 3a43683.

## Cause

Docker's event log for the maintainer's run (one Ctrl-C in `docker compose up`)
shows SIGTERM to `curriculum-registration`, `slo-rest-api` and `slo-search` at
12:36:20 and SIGKILL at 12:36:30; `curriculum-store` received SIGTERM at 12:36:30
and SIGKILL at 12:36:40 (exit 137, not OOM). Its container command was
`npm install\nnpm start\n`, with the trailing newline from the YAML `|` block.

A throwaway `node:24-alpine` container with the same entrypoint and a Node
script that logs signals:

| Command | PID 1 | Stop | Exit | Node received |
| --- | --- | --- | --- | --- |
| without trailing newline | `npm start` | 0 s | 0 | SIGTERM |
| with trailing newline | `/bin/sh -c …` | 10 s | 137 | nothing |
| with trailing newline and `exec npm start` | `npm start` | 0 s | 0 | SIGTERM |

## Result

`docker compose config` accepts the changed file. The actual compose file was
run with an override that only renames the `curriculum-store` container and
port and mounts a disposable copy of curriculum-store (0.11.1, the local
dataset without its stale lock), under a separate project name. After startup
and four queries, PID 1 was `npm start` with Node as its child. SIGINT to
`docker compose up`, as Ctrl-C sends, stopped the service gracefully in 236 ms
with exit 0, and the store lock directory was removed.

Separately, SimplyStore on the same copy released its lock when stopped after
startup and 16 queries (0.3 s) and during a normal query (about 1 s). With a
slow query running, close took 9.9 s, which the new 30 s grace period covers.

The other three services received the same `exec` change; their stop behavior
was not run end to end because it would install into and start the real
service directories. The mechanism is identical and was shown by the probe.

## Limits

A stop during SimplyStore's startup, before it installs its signal handlers,
still leaves the lock (reproduced at 0.5–2.5 s; startup took about 3 s). Real
crashes still require the documented administrator unlock. The existing stale
lock in the local dataset was not touched.
