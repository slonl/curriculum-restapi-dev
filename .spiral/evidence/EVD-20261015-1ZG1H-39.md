## Disposable Compose exercise

The committed `node scripts/verify.mjs --smoke-only` path passed against a
temporary copy of the tracked 77 MB Store baseline:

- all four services installed dependencies and started;
- Store accepted a normal query;
- authenticated REST object retrieval succeeded;
- REST-to-Search integration returned an array;
- Registration returned its expected 400 response for a missing email;
- an authenticated REST patch progressed to `done`;
- the changed title and command metadata appeared in object history;
- after restarting Curriculum Store, both the title and history remained;

  removed; and
- parent and all child Git status snapshots were identical before and after.

The smoke runner uses a unique Compose project, ports, credentials, log path,
dependency directories and Store data directory. It invokes only project-bound
`docker compose down --volumes`; it does not call `docker-clean.sh`.

the empty command log/status files required by a new SimplyStore baseline; the
second used Fetch's generic `Accept` header and received the intended HTML data
browser instead of API JSON. Both failures stopped before an edit, printed
service logs, retained their temporary directories, and cleaned up only their
own Compose projects. The fixture and client were corrected without changing
application behavior.
