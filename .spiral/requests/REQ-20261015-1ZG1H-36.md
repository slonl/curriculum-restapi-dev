# Request: trustworthy integrated development verification

Provide one documented verification command in `curriculum-restapi-dev` that
gives an unambiguous result for the exact pinned development stack without
altering the maintainer's working dataset.

The result is successful when:

- the REST API and Curriculum Store behavioral suites report their real
  assertion result without an implicit 100% coverage gate;
- coverage remains available through an explicit separate command;
- a separately invokable target check reports whether statements, branches,
  functions, and lines have reached 90%, without hiding the current gap or
  making that gap indistinguishable from behavioral test failure;
- lint and Compose configuration checks run where they are meaningful;
- a disposable-data Compose exercise starts the integrated services, performs
  an authenticated edit through the REST API, observes its audit history, and
  verifies persistence after a Curriculum Store restart;
- Registration and Search receive at least runtime/startup integration
  coverage despite having no component suites; and
- verification leaves tracked source, the development dataset, and all
  pre-existing untracked artifacts unchanged.

The verification must isolate its Compose project and cleanup. It must not use
the repository's machine-wide `docker-clean.sh` command.

Cheap, meaningful coverage improvements discovered in this work are welcome,
but closing the full current gap to 90% is not required when it would displace
the integrated-verification outcome. Adding complete Registration or Search
suites, browser UI automation, Excel import/export testing, deployment,
production-data testing, and application refactoring are outside this request.
