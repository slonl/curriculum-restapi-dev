# Request: FO Deprecated Replacement Probe

## Operationalized Intent

Produce a limited, evidence-grounded set of candidate replacements for FO
deprecated entities that currently have no `replacedBy`, using both semantic
comparison and Git history timing.

## Upstream Understanding

The request is a narrower continuation of the semantic-continuity feasibility
work. It should test whether AI/history-assisted review can help fill likely
missing continuity links inside FO without mutating data.

## Intended Audience

The maintainer and future maintainer-workspace roadmap decisions.

## Observable Desired Outcomes

### candidate-shortlist

A small shortlist of FO deprecated entities without `replacedBy`, each with
candidate active replacement entities where plausible.

### history-evidence

For each useful candidate, the evidence includes relevant Git timing: when the
deprecated entity was removed or entered `deprecated.json`, and when the
candidate appeared or changed where practical.

### uncertainty-classification

The output distinguishes likely candidates, weak candidates, non-links, and
cases where Git/data evidence is insufficient.

## Assumptions / Ambiguity

| Claim | Provenance | Evidence / question |
|---|---|---|
| Missing `replacedBy` can indicate a possible missing continuity link | explicit | Maintainer suggested this as a suitable test subject |
| Git timing can help identify candidates | explicit | Maintainer noted candidates probably appear near the deprecation time |
| Some missing links are intentional | inferred | Deprecated entries can be delete-only or obsolete without successor |

## Non-Goals

- Do not edit FO data.
- Do not commit `replacedBy` additions.
- Do not attempt whole-dataset mapping.
- Do not build maintainer-workspace UI.

## Constraints Already Known

| Constraint | Source | Effect |
|---|---|---|
| Continuity links are trust-sensitive durable references | `SRC-002` / Cycle 2 | Candidates require human review |
| This is a limited test | `SRC-006` | Keep the sample small and auditable |
| Use Git history | `SRC-006` | Include temporal evidence where practical |

## Nearest Important Uncertainty

Whether useful candidate replacements can be found from active FO data plus Git
history for entities with no current `replacedBy`.

## Risks

| Risk | Horizon | Why It Matters | Evidence/Action |
|---|---|---|---|
| False positives | near-term | Bad continuity links harm durable references | Classify uncertainty and do not mutate data |
| Git history noise | near-term | Batch/generated commits can hide intent | Treat timing as support, not proof |
| Delete-only deprecated entries | near-term | Some entities may correctly have no successor | Include non-link / insufficient-evidence outcomes |

## Acceptance Shape

The cycle is acceptable if it produces a small, inspectable report with
candidate replacements, history evidence, and clear uncertainty limits.
