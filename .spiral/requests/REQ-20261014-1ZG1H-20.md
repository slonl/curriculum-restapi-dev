# Request: single-object audit trail

## Operationalized intent

Provide a complete, read-only audit trail for one current curriculum object,
available as a REST resource and as a simple view linked from that object's
existing browser page.

## Observable desired outcomes

### History API

`GET /uuid/:id/history` returns every stored version of the current indexed
object, oldest first. Each entry exposes:

- version number and dataset-file timestamp;
- `null` command for the base version, otherwise command ID, name, author,
  submitted commit message, timestamp and version; and
- the complete immutable object as it existed in that version.

An unknown current UUID returns 404. Store/query failures use the existing API
error boundary. The response is not cached.

### Audit view

The current object view has a visible `Geschiedenis` link. Its dedicated route
loads the history API, identifies the object, and renders every entry with
version, timestamp, author and message. The base entry is recognizable. Each
entry offers an expandable raw snapshot. Loading, empty and failure states are
visible and stale asynchronous results do not overwrite later navigation.

### Integrated dependency path

The embedded curriculum-store resolves published SimplyStore 0.12.0, proves
object history against curriculum-shaped data before and after restart, and
continues passing its existing suite. The REST API focused and existing suites
pass. The parent pins both resulting child commits and its Compose
configuration remains valid.

## Constraints

- Use existing API authentication; do not add an editor-only history grant.
- Begin with the currently indexed object rather than a free-standing command
  or historical-ID search.
- Keep the API unpaginated in this first version; existing SimplyStore query
  time, memory and result-size limits remain authoritative.
- Preserve current dataset, command-log, REST object and import/export formats.
- Keep the separate standalone curriculum-store checkout untouched.

## Non-goals

- Property-level diffs or schema-aware historical rendering.
- Restore, edit, rollback or historical command execution.
- A global command/audit browser or same-version peer listing.
- Original command input exposure.
- Complete historical dataset switching.
- IndexedDB work or general frontend modernization.

## Acceptance shape

The cycle is ready for evaluation when a real curriculum-store fixture records
multiple versions, the new REST endpoint returns those versions and metadata,
the browser route presents them from an object's link, and the parent can pin
and configure the verified child commits without unrelated changes.
