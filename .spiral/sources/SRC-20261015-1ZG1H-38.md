# Source: 90% coverage target

During planning for integrated development verification on 2026-10-15, the
maintainer added:

> lets set 90% coverage as a target, if we can.

This is interpreted as a transparent direction of travel, not permission to
exclude difficult production files, add assertions without discriminating
value, or make the ordinary behavioral test command fail until the target is
reached. The current measurements show that immediate universal enforcement
would materially expand this cycle: REST is about 86% statements/lines, 78%
branches, and 16% functions, while Store is about 68% statements/lines, 76%
branches, and 84% functions.

The cycle should therefore expose a 90% target check and retain the measured
gap. It may add cheap, meaningful coverage discovered while implementing the
verification path, but broad coverage uplift remains a separately evaluable
body of work unless evidence shows the gap can be closed without obscuring the
agreed integrated-verification goal.
