## Plan

### Goal

Make the REST API's standard `npm test` command trustworthy and green by
updating stale change-history setup to the append-only API actually used in
production, while proving that append-and-merge behavior remains correct.

### Work

1. Replace only the two constructor-array setups with explicit hydrated appends.
2. Keep the existing length and merged-property expectations unchanged.
3. Run the focused legacy test, full default suite, and lint.
4. Pin the verified REST API child commit in the parent and record evidence.

### Evaluation basis

The focused test and complete `npm test` command pass with the existing
behavioral assertions, lint is clean, production files are unchanged, and the
parent pins exactly the verified child revision.

### Non-goals

- Restoring array hydration as a production constructor API.
- Changing persistence, browser behavior, IndexedDB work, or dependencies.
- Modifying curriculum-store or its runtime files.
- Acceptance, merge, push, publication, or deployment.

### Pause conditions

Return to analysis if the incremental setup fails the existing merge assertion,
if production code must change, or if the full suite exposes a new failure.
