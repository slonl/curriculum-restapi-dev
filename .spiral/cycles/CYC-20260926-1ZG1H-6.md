# Clean Docker service shutdown

Branch: `spiral/CYC-20260926-1ZG1H-6-compose-shutdown`, created from `main` at
929314f. Branch identity checked when opening the cycle.
Status: Accepted and closed by the maintainer on 2026-10-14.

Goal: one Ctrl-C or `docker compose stop` stops every service cleanly, so
curriculum-store's SimplyStore releases its lock; after a forced store crash,
the next `docker compose up` starts the store without manual lock removal when
the previous owner is provably dead (REQ-20260926-1ZG1H-5).

The maintainer instructed the shutdown change after reviewing the investigation
and later explicitly extended the same cycle to self-healing startup. This is
bounded local Docker plumbing, consistent with the intake's treatment of Docker
as local-only. No governing multi-cycle roadmap is confirmed; this does not
reopen other work.

## Shutdown evaluation (complete)

The change at 3a43683 runs `exec npm start` in all four services and gives
curriculum-store a 30 s stop grace period. EVD-20260926-1ZG1H-7 records the
cause from Docker's event log and an end-to-end Ctrl-C through the actual
compose file: exit 0 in 236 ms, lock released. Retained, not absorbed:
SimplyStore's startup window, real-crash recovery, the local stale lock and the
curriculum-store submodule pin. This evidence completes only the original
shutdown portion of the goal; it predates the extension below and does not
evaluate crash recovery. Acceptance and integration remain the maintainer's
decisions.

## Goal extension

After evaluation, the maintainer kept the cycle open: "Keep the cycle open, I
think the self healing part should be included in it." Asked how to organize
the cross-repository work, the maintainer chose a chain of cycles and declined
a restart policy: "the docker-compose and restapi-dev are only for development,
no restart needed here".

Extended goal: after a stop or crash that prevents normal lock cleanup, the
next `docker compose up` starts curriculum-store without manual lock release
when the previous owner is proven gone. The mechanism belongs to SimplyStore
(its own cycle and release);
curriculum-store then updates its lockfile. This cycle updates the
curriculum-store submodule pin, previously out of scope, and evaluates the
chain end to end: a store killed with SIGKILL starts again on the next `up`.
No restart policy is added. The shutdown evaluation section above describes
the earlier shutdown-only state.

## Extended evaluation (ready)

The change at 76e21b1 updates the curriculum-store submodule from f5958f8 to
b3d6faa. That release line uses SimplyStore 0.11.2 and includes runtime tests
for conversion, integrity, queries, commands, persisted indexes, and restart
readback.

EVD-20261014-1ZG1H-8 records the end-to-end Compose evaluation with disposable
data. The initial store answered an application query. SIGKILL then produced
exit 137 and left its ownership lock intact. The next `docker compose up`
succeeded without lock removal: SimplyStore recorded `ECONNREFUSED` as proof
that the previous owner's socket was gone, took ownership, and returned the
same query result. A final graceful stop exited 0 and removed the new lock.

This covers both the original clean-shutdown criteria and the extended
SIGKILL-to-next-`up` criterion. No automatic restart policy was introduced.
The protected cases listed in the request remain outside automatic takeover.
The cycle was ready for maintainer evaluation; readiness did not imply
acceptance or authorize integration.
