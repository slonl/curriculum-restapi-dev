## Plan

### Goal

Provide one documented verification command in `curriculum-restapi-dev` that
gives an unambiguous result for the exact pinned development stack, including a
disposable-data Compose edit/history/restart exercise, without altering the
maintainer's working dataset or pre-existing artifacts.

### Likely work

1. Align the parent REST gitlink with current `master`.
2. Separate behavioral test success from explicit coverage reporting in REST
   and Store.
3. Add parent orchestration for child tests, lint where meaningful, and Compose
   configuration validation.
4. Prove Compose isolation with temporary Store data, credentials, project
   identity, and ports.
5. Exercise service readiness, REST/Search reads, authenticated edit and
   polling, audit history, Store restart, and persisted readback.
6. Bound cleanup to the test Compose project and verify repository state is
   unchanged after the run.
7. Record exact verification evidence and limitations.

The likely work is a hypothesis rather than a fixed task list. The stable scope
is the goal and non-goals below.

### Evaluation basis

The cycle succeeds when one documented command runs the behavioral checks and
the isolated Compose exercise; a disposable authenticated change becomes
queryable and visible in object history after Store restart; all involved
services receive meaningful runtime coverage; an injected failure is surfaced;
and every source checkout plus the real development data retain their starting
Git state.

### Non-goals

- Raising coverage materially.
- Complete Registration or Search component suites.
- Browser/Selenium automation.
- Excel import/export verification.
- Deployment, production data, or application architecture changes.
- Machine-wide Docker cleanup.
- Deleting or normalizing the maintainer's existing Store artifacts.

### Pause and re-plan conditions

Return to discourse if isolation requires persistent-format changes or a broad
Compose redesign; credentials or commands cannot be separated from real data;
dependency installation makes the test mutate lockfiles or remain inherently
non-repeatable; or the probe exposes a functional component failure rather than
the known coverage-policy mismatch.
